# MEM-REFLECTION：跨多則訊息的習慣歸納（D7 主動發現 B）

日期：2026-10-29。狀態：LOCAL_VERIFIED（合成訊息）/ NOT PUSHED。計畫：[CONSOLE-REDESIGN-PLAN](../../collaboration/CONSOLE-REDESIGN-PLAN.md) §5 D7。
實作：`src/siro/services/agent/reflection.py`，沿用既有 `core/consolidation.py` 與 `persistence/consolidation.py`。

## 規則

- 閒置（沒有前景對話、沒有背景規劃）且累積 20 則新的主人訊息時才跑。20 是設計選擇，沒有外部來源。
  每 300 秒檢查一次；監控頁可手動「現在反思」。
- 讀最近 60 則主人自己的訊息（只讀 `siro.presentation`，工具結果等不算），請模型列出至少出現在兩則不同訊息的習慣，
  並附訊息編號。程式核對：編號必須有效且不重複、至少兩個；憑證、敏感個資、控制語句一律丟棄。
- 寫入走既有 Consolidator：標記為推測（`inferred`）。來源少於 3 則時存成 `candidate`，不會帶進對話；
  3 則以上才 `committed`。同一輪重跑不會重複寫入。
- 依據：Generative Agents 由多筆觀察合成較高層的反思；OpenClaw dreaming 只把反覆被想起的候選升為長期記憶，
  不可信與系統衍生的候選不升級。

## 量測

`evaluate.py`：18 則合成訊息，埋了 3 個各出現 3 次的習慣（早上跑步、只喝綠茶不喝咖啡、週六打給媽媽），
以及 5 個誘餌（一次性看牙醫、中樂透的假設、同事愛香菜、外星人玩笑、環遊世界）。本機 `gemma4:e4b`，每版 5 次。

| | v1 提示（列出支持的編號，至少兩個） | v2 提示（列出「所有」支持的編號） |
| --- | --- | --- |
| 找到的習慣 | 14／15（有一次寫成空泛的「主人有定期的行動或活動」） | 15／15 |
| 誘餌被當成習慣 | 0 | 0 |
| 達到 3 則來源、會被採用 | 0／15（每次都只列 2 個編號） | 15／15 |

v1 的結果代表：所有反思都會停在候選，永遠不會被使用，所以改用 v2。
v1 的 JSON 檔被我誤刪，`evaluation-v1-gemma4-e4b.log` 是該次執行的主控台輸出原文；v2 有完整 JSON 與 log。

## 限制

- 只有一組 18 則的合成訊息，模型只測 `gemma4:e4b`。真實對話中習慣分散、用詞不同，抓到率可能較低。
- 觸發門檻（20 則新訊息）與讀取範圍（60 則）未經校準；之後依監控頁的實際反思紀錄調整。
- 推測出的習慣可在「SIRO 記得的事」刪除；候選狀態的不會出現在那裡（只在監控頁「SIRO 的反思」看得到）。
