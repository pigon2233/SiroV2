## 需求與現況

使用者要求重新設計介面、加入未完成工作，**不同目的不要放在同一個畫面**；Live2D 的存在形式參考 VPet。沿用先前要求：角色能自己選擇在螢幕上走動、休息與互動，缺少的動作由我們製作；單純常駐視窗、站姿平移或假的角色切換不算完成。

讀碼基準：`215aaa9d305073b41a44f242387051ea836dc035`。目前 `src/siro/services/presentation/static/index.html:45–116` 把角色、聊天、電腦、任務、改善建議、技能、工作目錄、記憶與診斷接在一頁，主要靠 `details` 折疊。`refreshProduct()` 與 WS handlers 還直接更新各區 DOM（約 847、920 行）。因此只換 CSS 或移除其他頁的 DOM 都不足：前者仍過載，後者可能使回呼存取不存在的元素。

原 [EXPERIENCE](../EXPERIENCE.md) 允許合併控制 UI；本次需求取代「所有功能集中單長頁」的解讀。可共用一個應用程式與導覽，但同一時間只呈現一個主要工作畫面。既有傳輸、來源、批准、取消與持久化成果繼續使用，不因此重做 Core。

## 畫面與導覽

日常以角色和談話為主。控制應用的主導覽為「對話／任務／記憶／能力／設定」；能力與設定下的不同工作仍有各自畫面。桌寵是獨立表面，不是塞滿全部控制項的另一個控制台。

下列為**完整目標的前端 hash routes**，不代表新增 HTTP API。第一切片已接通九個工作畫面；task detail 與層級路徑尚未實作，實際入口差異見接續點。沿既有 `/` 入口，不為分頁引入新框架；hash 不放 token、私人對話或來源內容。桌寵宿主入口待既有平台切片驗證後決定。

| 畫面／擬議路徑 | 主要工作與資訊 | 現有內容的去處 |
|---|---|---|
| 螢幕角色／原生表面 | 自選活動、短氣泡、點擊、叫回、拖曳、暫藏／停止活動；開啟對話或指定任務 | Live2D 的主要存在形式；遵守唯一 body／音訊 owner |
| 對話 `/#/chat` | 歷史、輸入、麥克風、字幕、回覆／語音停止與實際連線狀態 | 現有聊天；瀏覽器取得 body owner 時才呈現角色，桌寵模式不再開第二 renderer |
| 任務 `/#/tasks`、`/#/tasks/<id>` | 清單→詳情→來源／步驟／批准→進度／結果，暫停、繼續、取消 | D57 任務；「已讀取文件」與「待辦已執行」持續區分，unknown 不變成功 |
| 記憶 `/#/memory` | 搜尋、來源、時間、更正／刪除；整理狀態為次要資訊 | 原始記憶與閒置整理；不是把整理開關當作記憶首頁 |

| 電腦 `/#/computer` | 能力範圍、讀檔、目前 action／審計 | 現有電腦協助與指定工作目錄；不因 UI 改名擴張 scope |

Devices、Setup、正式 release 等既有未完成流程保持原卡與 gate；需要時從能力／設定進入各自畫面，不能用新空殼頁宣告能力完成。能力中未接通的項目要說明限制，不能捏造成功紀錄。

## 視覺方向草案

對象是日常陪伴 SIRO 的擁有者；首要工作是自然互動、看懂她正在做的事並能介入。風格採安靜、有生活感的陪伴介面。角色是最鮮明的元素，周圍保持留白；任務用清楚列表與來源，記憶用可閱讀紀錄，設定用分組表單，不套用相同大卡片。

以下是原型起點，尚未經角色畫面或對比檢驗，不能稱最終設計：

| token | 草案值／角色 |
|---|---|
| `--color-page` | `#F3F6FA`，安靜的冷白底 |
| `--color-surface` | `#FFFFFF`，內容與對話表面 |
| `--color-text` | `#27344A`，主文字 |
| `--color-muted` | `#53627A`，輔助文字 |
| `--color-action` | `#365D8D`，操作與可見焦點 |
| `--color-character` | `#E5B6C8`，保留現有角色粉色，限裝飾與非文字背景 |

沿用 `Noto Sans TC` 與系統 fallback，針對繁體中文調整字重、行高與疏密，不增加字型外送。原型以 16px 內文、14px 輔助、22／30px 標題和 4／8／12／16／24／32px 間距起步；長文字左對齊，閱讀寬度有上限。深色模式另配完整 token 並實測，不能直接反相。成功／警告／錯誤的語意色在原型階段補齊對比與文字／圖示辨識，這六色不是全部狀態的完成證據。

自我檢討：現行「暗色漸層＋同形卡片＋裝飾小標」沒有充分呈現她的角色。草案改以角色與對話的生活感為主，移除儀表板式開場；保持同一套視覺語言，同時讓任務和記憶各有適合的密度。這只是設計推理；之後仍須用真畫面截圖、中文長內容與使用者操作檢討，不能以設計 skill 的自評分數取代驗收。

## Live2D 與自由活動

直接承接 [COMPANION_EVOLUTION_PLAN](COMPANION_EVOLUTION_PLAN.md) 的「桌面場景原型／全身與動作製作／自由活動桌寵」，不新增另一套角色架構。

- 參考 VPet 的活動連續性：起步→有步態走到位置→停步／轉向→休息或玩道具。走動不等於取得其他程式的點擊、螢幕內容或檔案權限。
