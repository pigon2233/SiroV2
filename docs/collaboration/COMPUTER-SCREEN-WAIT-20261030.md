## Result

- Added experimental `SIRO_COMPUTER_SCREEN_GUARD=1` (default OFF). After the model chooses an action but before any input is sent, the loop re-observes and waits up to 30 seconds for the same decoded PNG pixels, image geometry, title, process, handle and process id. If matched, it sends the previously unexecuted action once using the newest observation. A mismatch, timeout, missing identity/image, blocked window, control disable or emergency stop does not send the action. Unknown input outcome still stops; it is never replayed.
- This is a proposed response to a short recurring screen disappearing during cloud inference. Exact pixels are deliberately conservative and can fail whenever the target animates, cursor/capture rendering changes, or the screen returns after 30 seconds. Matching pixels do not prove hidden game state is unchanged or the selected action is correct. There remains a race between the final capture and OS input; the paired desktop window fence reduces but does not eliminate it. This is not a real-time controller or a guarantee against wrong game decisions.
- Prior to the change, a fake-desktop scenario with the screen changing during inference sent one input immediately after only one observation. The opt-in implementation waited for the third observation, when the original screen returned. Additional fake tests cover a scene that never returns, same pixels in a different window, missing/invalid pixels/identity, owner disable, stop/re-enable and unknown outcome; status exposes `waiting_for_matching_screen`.
- A synthetic 1280x720 single-color frame digest on this WSL machine, 10 warm iterations: median 6.53 ms, max 7.83 ms. This excludes screenshot acquisition, transport, scheduling and gameplay; CPU load and complex images may differ. PNG decoding runs in a worker thread and retains pixels only in memory.
- `PYTHONPATH=src ~/.venvs/sirov2/bin/python -m pytest -q tests/unit/test_computer_use*.py tests/unit/test_undertale_fast_cue.py`: 172 passed, one Starlette deprecation warning. Scoped Ruff format/check passed.
- Scoped mypy initially reported two errors caused by reusing an exception variable name in the guard path. Renamed the local variable and reran `mypy --follow-imports=silent` on the three changed source files: no issues. The seven targeted guard cases passed again after the rename.
