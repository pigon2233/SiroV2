# 本地學習玩遊戲（方案 C）— 可行性與階段計畫

狀態：階段 C1 已實作（資料錄製，預設關閉）。其餘階段未做，成功與否**未知**，下面都是設計與假設，不是已量測成果。

## 目標與現實
目標：她本人（本地模型）學會某款遊戲的操作，不依賴雲端每步決策。現況是 Claude 逐步看圖決策（約 7–10 秒/步），
只有「玩法筆記」會累積，沒有任何權重被訓練。

可用硬體：RTX 3050 8GB（本機 WSL 已有 CUDA）。夠訓練小型 CNN，不夠訓練大型視覺模型。

## 做法（行為複製 → 視需要加強化學習）
1. **資料**：每一步的（縮小畫面、動作、動作後畫面是否改變、Claude 的「看到什麼」）。
   - 來源 A：Claude 的操作（已可錄，約 0.1 步/秒，資料稀疏，適合回合制/選單）。
   - 來源 B：owner 自己玩（10–20 幀/秒的畫面＋遊戲按鍵）。對即時遊戲才夠密，但要錄鍵盤，隱私風險高，必須嚴格限制（見下）。
2. **模型**：每款遊戲一個小型 CNN（輸入約 96×72 灰階、疊 4 幀，輸出各按鍵是否按下），行為複製訓練；先離線評估動作預測準確率。
3. **執行**：在 Windows 側以 20–30 Hz 跑小模型當「反射層」，Claude 負責高層目標與換場景；兩者以優先權仲裁，急停永遠最高。
4. **評估**：留出一部分錄製做離線準確率；再用一個固定的實機小任務（例如 Undertale 廢墟走到某處、躲一個固定彈幕）量成功率與存活時間。
5. 若行為複製不夠，再考慮在同一款遊戲上做強化學習（需要可重置的場景與獎勵訊號，成本高）。

## 誠實的風險
- 只對**固定的少數遊戲**有機會；換遊戲要重新收資料、重新訓練。
- 即時遊戲需要大量示範（以小時計）；Claude 的稀疏資料不足以學即時反應。
- 沒有可靠的「獎勵」時，只能模仿；模仿者不會比示範者好。
- 這是研究型工程，不保證達到可用水準；每階段都有量測關卡，不達標就停。

## 隱私與安全底線（資料錄製）
- 預設關閉（`SIRO_COMPUTER_RECORD=1` 才錄）；只錄白名單程式；只存本機（`SIRO_DATA_DIR/computer-demos/`），不外送。
- 不存視窗標題；打字內容只存長度；畫面縮到 320 寬。
- 上限：最多 40 次任務、1.5 GB，超過自動丟最舊的；可用 `GET/DELETE /v1/computer/demos` 查看與刪除。
- 來源 B（錄 owner 鍵盤）另外要求：只在白名單遊戲在前景時、只記遊戲用到的固定幾個鍵、需 owner 明確啟動/停止並有可見指示；**未實作，需 owner 明確同意才做**。

## 階段
| 階段 | 內容 | 關卡 |
|---|---|---|
| C1（已做） | Claude 操作的資料錄製、查看、刪除、容量上限 | 單元測試；錄出的資料格式可被訓練腳本讀取 |
| C2 | 資料集工具：載入、統計、抽樣檢視、切分訓練/驗證 | 能列出每款遊戲的樣本數與動作分布 |
| C3 | （需 owner 同意）owner 示範錄製器，限定遊戲與按鍵 | 實機錄 10 分鐘，確認不錄其他視窗與按鍵 |
| C4 | WSL 訓練小型 CNN（行為複製），離線評估 | 驗證集動作準確率高於「永遠按最常見鍵」的基準 |
| C5 | Windows 反射層執行與仲裁、急停優先 | 實機成功率高於基準；可隨時停用 |
