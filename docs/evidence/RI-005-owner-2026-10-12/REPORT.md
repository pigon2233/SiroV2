## D. Implementation and compatibility boundary

`adapters/data_ownership.py` provides one local context. Its namespace uses pwd's effective-UID account home `.local/state/siro/data-owners`, not HOME/TMPDIR/XDG authority. This avoids PrivateTmp splitting and preserves D49's absent-target-directory behavior. Keys use canonical filesystem bytes; directory700/empty stable lock600, regular/sameUID/single-link checks, O_NOFOLLOW/CLOEXEC and exclusive nonblocking flock. Close-only; never unlink/replace/unlock a shared description, guess stale PID/TTL, kill a process or retry unknown effects.

Source, optional explicit write target and optional deterministic ZIP temporary write target are captured together, sorted and deduplicated (max3). Raw SQLite backup uses exclusive mkstemp and adds no deterministic third key. Partial acquisition failure cleans acquired descriptors before body effects. One resource owns all keys through IO completion; nested contexts cannot release one early. Its explicit standard loop factories own only their captured default ThreadPoolExecutors. Gateway initialization and server loops, and the three CLI async handlers, use those factories. A dedicated non-daemon join thread completes shutdown(wait=True,cancel_futures=True); repeated main-thread KeyboardInterrupt retains all FDs and primary error. Unknown pool completion retains all FDs until process exit. No thread/process scan or global event-loop policy change.

Installed Uvicorn0.53.0 actually accepts this callable via Config.get_loop_factory/import_from_string; its narrow published annotation requires one documented local type-ignore. Actual offline HTTP proves invocation. No dependency change, broad suppression, cast to string or alternative server framework.

Valid handler shapes/APIs remain unchanged. New fixed failures: data_in_use, data_owner_unavailable, invalid_backup_destination, invalid_restore_configuration.
