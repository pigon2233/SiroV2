# Quoted numeric-key fixture portability review

Classification: MINOR_FIX / TEST_GAP (a version-specific intermediate assertion), within the existing CI repair card. No production SQL guard regression or architecture/design error was found.

The original fixture attaches a prior journal call containing numeric 2**80 under an object key containing a literal quote to a different proposal containing 2**80+1. It requires the fresh automatic proposal to remain pending with PriorOutcomeUnknown, no effects and an identical full SQLite dump. Both JSON-tree numeric atoms collide as floating-point values. SQLite3.46.1 cannot extract either quoted-key numeric lexeme; SQLite3.50.4 can extract each exact integer text. Consequently the old additional assertion that both extractions must be NULL describes an older engine limitation, not the authorization invariant.

The official [SQLite JSON documentation](https://www.sqlite.org/json1.html) describes the -> result as JSON text and NULL for absent components. The official [quoted-key discussion](https://sqlite.org/forum/forumpost/4337036367?hist=&t=h) independently documents improved quoted-label handling around3.47.0; this review does not infer the exact remote engine version from that discussion. Modern3.50.4 source came from the official amalgamation URL, and its sqlite3.c SHA3-256 matched the official [3.50.4 release record](https://www.sqlite.org/releaselog/3_50_4.html). It was compiled only in an owned temporary directory and loaded only into disposable probe children; no project SQLite/Python dependency, version, lockfile or production SQL changed.

Before repair, the exact public d1f5d07 testcase passed on3.46.1 and failed on3.50.4 at the both-NULL assertion. Actual original guards on both engines independently raised PriorOutcomeUnknown and preserved PENDING/full-dump/effects invariants. The minimal repair renames the testcase to quoted-numeric-key and requires each extraction to be NULL or its own exact expected integer text. Incorrect/imprecise extraction still fails; different payloads still require the original complete automatic-hold assertions. There is no version branch, skipped case, mocked operator, reduced limit or new parser.
